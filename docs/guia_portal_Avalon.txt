OBJETIVO DESTE GUIA
-------------------

Este arquivo explica, passo a passo e sem pular etapas, o processo que você deverá
repetir sempre que uma nova Raid terminar:

1. preparar o projeto;
2. revisar membros da guilda;
3. colocar as imagens;
4. executar o OCR;
5. conferir e corrigir dados;
6. promover a nova Raid;
7. testar o Portal;
8. fazer commit;
9. enviar para o GitHub;
10. verificar o deploy.

REGRA DE OURO
-------------

Nunca faça a promoção da nova Raid antes de conferir:

- o CSV bruto;
- o CSV revisado;
- o relatório JSON;
- os nomes;
- as frequências;
- os danos;
- se existem pendências.

O sistema é automatizado, mas a conferência humana continua sendo a trava final de
segurança.

=================================================================

2. Abra o terminal PowerShell dentro do VS Code.

3. Confirme que o terminal está na pasta do projeto. Deve aparecer algo parecido:

4. Ative o ambiente virtual que está nos Documentos:

PARTE 3 — SEGURANÇA ANTES DE COMEÇAR UMA NOVA RAID
=================================================================

Antes de alterar imagens, membros ou dados, execute:

Primeiro descubra de onde vieram essas alterações.

Também é recomendado manter uma cópia ZIP da versão aprovada antes de iniciar uma

PARTE 4 — REVISANDO OS MEMBROS ANTES DO OCR
=================================================================

Antes de cada nova Raid, verifique:

- entrou algum membro novo?
- alguém saiu?
- alguém mudou de nick?
- existe algum nome que o OCR costuma ler errado?


---------------------------------------------------------------
CASO A — NENHUMA MUDANÇA DE MEMBRO
---------------------------------------------------------------

Não altere o config.py.

Pode seguir diretamente para as imagens.


---------------------------------------------------------------
CASO B — ENTROU UM MEMBRO NOVO
---------------------------------------------------------------

Abra:

ocr\guild-rank-ocr\src\config.py

Localize:

NOMES_VALIDOS = [

Adicione o nick oficial exatamente como aparece no jogo.

Exemplo:

NOMES_VALIDOS = [
    "Cley",
    "Hela",
    "NovoMembro",
]

Se o nome tiver formas que o OCR pode confundir, adicione aliases em:

ALIASES_MEMBROS = {

Exemplo:

ALIASES_MEMBROS = {
    "NovoMembro": ["Novo Membro", "Novo-Membro"],
}

IMPORTANTE:

- o nome principal deve ser o nick oficial;
- aliases são apenas variações de leitura;
- não invente danos antigos para o membro novo;
- ele ficará sem base histórica até acumular raids válidas;
- isso é esperado e correto.


---------------------------------------------------------------
CASO C — UM MEMBRO SAIU OU FOI BANIDO
---------------------------------------------------------------

Somente depois de confirmar a saída, abra:

ocr\guild-rank-ocr\src\config.py

Remova o nome de:

NOMES_VALIDOS

Não apague manualmente danos antigos dos JSONs.

Na próxima promoção, o sistema trabalhará com o elenco atual e reorganizará o
histórico conforme as regras do Portal.


---------------------------------------------------------------
CASO D — UM MEMBRO MUDOU DE NICK
---------------------------------------------------------------

Este caso exige mais cuidado porque o nick antigo pode existir nas raids históricas.

Procedimento seguro:

1. Faça backup ou confirme que o Git está limpo.
2. Em NOMES_VALIDOS, troque o nick antigo pelo novo.
3. Em ALIASES_MEMBROS, use o novo nick como nome principal e adicione o antigo
   como alias.

Exemplo:

"NovoNick": ["NickAntigo", "Outra variação"]

4. Antes de promover, revise os arquivos históricos que ainda possuem o nick antigo:

web\data\raids\raid_atual.json
web\data\raids\raid_anterior.json
web\data\raids\raid_history.json
web\data\raids\raid_manual_overrides.json

5. Altere somente o campo de nome, mantendo danos e frequências intactos.
6. Execute todos os testes.

ATENÇÃO:

Não faça uma substituição cega no projeto inteiro.
Não altere danos, frequência ou posição para “combinar” com o novo nick.
Se houver dúvida em uma mudança de nick, pare e peça uma revisão antes da promoção.


---------------------------------------------------------------
CORREÇÕES HISTÓRICAS MANUAIS
---------------------------------------------------------------

O arquivo:

web\data\raids\raid_manual_overrides.json

serve somente para correções históricas comprovadas, como uma frequência antiga
que você sabe com certeza.

Não use esse arquivo para:

- aumentar dano;
- melhorar evolução;
- favorecer patente;
- corrigir a Raid atual do OCR.

A Raid atual deve ser corrigida pelo bloco específico da Raid em config.py.

=================================================================

Use estes nomes:

img1.jpeg

Regras:

- extensões aceitas: jpeg, jpg e png.

Com 28 membros, normalmente serão usadas 4 imagens.

Com 29 ou 30 membros, será necessária a quinta imagem.

PARTE 6 — EXECUTANDO O OCR
=================================================================

Na raiz do projeto, entre na pasta do OCR:

cd ocr\guild-rank-ocr

Execute:

python -m src.main --raid 144 --ended-at 2026-11-18 --source official


Para uma Raid normal extraída dos screenshots oficiais, use sempre:

--source official


ARQUIVOS GERADOS

Para a Raid 134, serão criados:

output\csv\raid_134_bruto.csv
output\csv\raid_134_revisado.csv
output\json\raid_134.json
output\json\raid_134_relatorio.json


SIGNIFICADO DOS ARQUIVOS

raid_134_bruto.csv
Resultado original do Tesseract. Serve para descobrir o que o OCR leu.

raid_134_revisado.csv
Resultado depois das correções e normalizações.

raid_134.json
Arquivo validado que será usado na promoção.

raid_134_relatorio.json
Resumo da coleta: participantes, dano total, correções e pendências.


=================================================================
PARTE 7 — CONFERINDO O OCR
=================================================================

Abra lado a lado:

- screenshots;
- raid_N_bruto.csv;
- raid_N_revisado.csv;
- raid_N_relatorio.json.

Confira membro por membro:

[ ] nome
[ ] frequência
[ ] dano
[ ] posição
[ ] duplicidade
[ ] ausentes
[ ] total de participantes


NO RELATÓRIO, PROCURE:

"status": "validada"
"registrosPendentes": 0
"duplicadosDetectados": 0

Se houver pendências, não promova.


=================================================================
PARTE 8 — CORRIGINDO LINHAS QUE O OCR ERROU
=================================================================

Abra:

ocr\guild-rank-ocr\src\config.py

Localize:

CORRECOES_LINHAS_POR_RAID = {

Crie um bloco somente para a nova Raid.

Exemplo:

CORRECOES_LINHAS_POR_RAID = {
    134: {
        ("img1.jpeg", 3): {
            "nome": "Cley",
            "frequencia": "21/21",
            "dano": 6418524181,
        },
        ("img2.jpeg", 4): {
            "nome": "Ger",
            "frequencia": "21/21",
            "dano": 5432498592,
        },
    }
}

COMO ENTENDER A LINHA

("img2.jpeg", 4)

significa:

- imagem img2.jpeg;
- quarta linha visível dentro daquela imagem.

Não significa posição geral número 4 da guilda.


REGRAS DAS CORREÇÕES

- crie correções somente para linhas realmente erradas;
- copie os dados conferidos diretamente do screenshot;
- não copie o bloco de correção de uma Raid anterior;
- cada Raid tem seu próprio bloco;
- mantenha o CSV bruto como evidência.


REPROCESSANDO APÓS CORRIGIR

Como os arquivos da Raid já existem, use --force conscientemente:

python -m src.main --raid 143 --ended-at 2026-08-26 --source official --force

Use --force somente depois de conferir que está reprocessando a mesma Raid.

Repita a conferência até o relatório ficar validado e sem pendências.

=================================================================
PARTE 10 — PROMOVENDO A NOVA RAID
=================================================================

python tools\promote_raid_history.py `
  --new-current ocr\guild-rank-ocr\output\json\raid_144.json `
  --history web\data\raids\raid_history.json `
  --published-current web\data\raids\raid_atual.json `
  --published-previous web\data\raids\raid_anterior.json `
  --report ocr\guild-rank-ocr\output\json\raid_144_relatorio.json

O PowerShell usa o caractere de crase ` no final da linha para continuar o comando.


O QUE A PROMOÇÃO FAZ

- Raid X vira a atual;
- Raid Y vira anterior;
- histórico é rotacionado;
- limite de raids armazenadas é respeitado;
- raid_atual.json é atualizado;
- raid_anterior.json é atualizado;
- raid_history.json é atualizado;
- relatório registra que a Raid foi promovida.


A PROMOÇÃO SERÁ BLOQUEADA SE:

- relatório não estiver validado;
- houver pendências;
- número da Raid estiver ausente;
- número for igual ou menor que a Raid atual.

=================================================================
PARTE 11 — VALIDANDO OS DADOS APÓS A PROMOÇÃO
=================================================================

Execute:

python tools\validate_raid_history.py `
  --history web\data\raids\raid_history.json `
  --current web\data\raids\raid_atual.json

Resultado esperado:

erros: 0

Avisos podem aparecer por:

- base estimada;
- frequência antiga abaixo de 15/21;
- membro ausente em base antiga.

Avisos esperados não bloqueiam.
Erros bloqueiam o commit.

PARTE 14 — SEGURANÇA ANTES DO COMMIT
=================================================================

Primeiro veja o que mudou:

git diff --stat
git diff --check

Confira se não aparecem:

- .venv;
- __pycache__;
- screenshots;
- arquivos temporários;
- senhas;
- caches;
- imagens brutas;
- arquivos que você não reconhece.


SE APARECER SOMENTE AVISO DE FINAL DE LINHA

Mensagens como:

LF will be replaced by CRLF

normalmente são avisos do Windows, não erros.

Mas evite incluir arquivos que só mudaram por final de linha sem necessidade.


=================================================================
PARTE 15 — PREPARANDO O COMMIT
=================================================================

Adicione todas as alterações, inclusões e remoções:

git add -A

Revise o que está preparado:

git status
Get-ChildItem tools -File | Sort-Object Name | Select-Object -ExpandProperty Name
git diff --cached --stat
git diff --cached --check

Se git diff --cached --check não mostrar erros, faça o commit.

Exemplo:

git commit -m "Promovendo Raid 143 e atualizando o Portal Avalon"

Confirme:

git status
git log -1 --oneline

O esperado:

nothing to commit, working tree clean

PARTE 18 — PROBLEMAS COMUNS

Solução:

& "$env:USERPROFILE\Documents\AmbientesPython\raid_hall_venv\Scripts\Activate.ps1"

Solução:

Não crie .venv dentro de raid_hall.

C:\Users\Claudio\Documents\AmbientesPython\raid_hall_venv


ERRO: A Raid já possui arquivos processados

Isso é uma proteção.

Primeiro confira os arquivos existentes.
Use --force apenas se deseja conscientemente reprocessar a mesma Raid.


ERRO: Promoção bloqueada

Confira:

- relatório validado;
- registrosPendentes igual a zero;
- número da Raid;
- se a Raid é superior à atual.


ERRO: JSON não aparece no site

Use Live Server ou:

python -m http.server 8000 --directory web

Não use file://.


ERRO: OCR não reconhece um nome

1. confira se o nome está em NOMES_VALIDOS;
2. adicione alias quando fizer sentido;
3. corrija a linha dentro do bloco da Raid;
4. reexecute com --force;
5. confira novamente bruto, revisado e relatório.
